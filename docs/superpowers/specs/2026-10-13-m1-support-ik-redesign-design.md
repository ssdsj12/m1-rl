## 1. 目标和不变条件

先得到能够在原物理环境完成真实10cm跨越的独立教师，再进入学生预训练、撤除教师及纯PPO。不得把失败教师的数据当作合格示范。此规格只重设计教师的支撑姿态参考和IK，不实现BC或开启PPO。

- 保留原机器人资产、质量、重力、PD、关节限位和初始rootZ `.62m`。主动降低机身通过关节动作完成，不改reset姿态、不直接写根部位置、不施加扶持外力。
- 保留16维控制接口：12个腿关节、4个轮速；教师允许按既有阶段停轮。正式学生及PPO最终不保留教师、IK或参考轨迹接管。
- 保留平地到10cm课程、8个目标加70个物理填充、20s回合、零额外净空、真实三轮支撑、无碰撞/穿透、经过障碍及远侧5帧稳定恢复。感知预测或IK可达不等于成功。
- 保留每碰撞控制步扣2分、实际累计20重置、耗尽同帧不额外扣termination20；其他物理失败和timeout规则不变。
- 不新增MPC、WBC、AMP、力矩优化器或新的物理控制层。不改学生观测维数、奖励和探索std。
- 所有旧PT、日志保留；旧训练及自动监控仍暂停。独立原生验证与训练严格串行。

## 2. 已有证据与设计针对性

源码中存在将锁定heading坐标下的位置误差直接减到完整body坐标轮目标的混用；IK判定前body_age已推进，拒绝时参考仍可能继续漂移。run2冻结测量复算发现目标需求长度超过相应两连杆长度；run3先IK_INVALID、后失支撑/碰撞，但缺少被拒绝解的完整原因，不能把run2超长数值套给run3。

因此本设计统一坐标、联合检查四腿可达性，并把请求、被接受参考及实测状态分离。它是待验证的修正方案，不宣称已证明摔倒的唯一原因或保证跨越。

## 3. 模块和数据流

### 3.1 只读测量与支撑观测

适配器为每行提供root位姿/速度、关节实角、上一帧实际执行的关节目标、轮位置/载荷、课程事件，以及真实质量加权COM。上一执行目标必须来自动作应用路径的实际处理结果，不能用当前实角或未执行的请求替代；reset后使用实际reset目标。

COM由`body_com_pos_w`与`root_physx_view.get_masses()`按一致body顺序计算。名称、形状、有限性、质量和四元数必须校验；缺失则该行测量无效，不用root位置冒充COM。可复用现有`m1_support_observer.py`的只读测量数学，不重新启用旧控制器。测量不step、不reset、不更新tracker，也不向学生actor增加特权信息。

准备抬某轮时，以其余三轮中心XY投影构成支撑三角形。此为平地投影近似，不是精确接触面或动态稳定证明。沿用每个支撑轮Fz>30N、横向合力不超过向上载荷等教师门槛；退化三角形或无效测量直接拒绝准备。新增COM投影向内至少10mm的准备余量，必须实测达到，不只检查预测COM。

### 3.2 显式机身目标生成器

输入测量、上一有效参考、当前阶段及活动轮；输出候选root位姿、四轮world目标和有界拒绝原因。按env/episode保存参考，单行reset仅清该行。

先沿用四轮承重、root速度范数≤.05m/s、倾角≤.15rad、角速度≤.20rad/s的刹稳条件，再捕获参考。期望yaw锁定捕获方向；期望roll/pitch渐进回到0，不将持续倾斜的实测姿态当作新的期望。

本版提出的首轮教师目标范围（不是物理限位变更）：

| 项目 | 相对捕获参考的允许范围 |
| --- | --- |
| 前后位移 | ±.04m |
| 侧移 | ±.06m |
| 降低机身 | 最多.08m，且不低于当前环境名义root高度减.08m |
| 向上抬高机身 | 不高于捕获高度 |

名义高度包含环境origin，不把某个绝对world Z当成所有环境地面。恢复时可回到捕获高度，但不能越过上界。

准备姿态采取有限、确定性的候选搜索：在上述X/Y范围各取5个等距偏移，降低量取0/.02/.04/.06/.08m，过滤高度下界，并额外加入上一接受姿态，共不超过126个候选。候选先过滤预测COM投影余量和四腿IK有效性，再按相对上一接受参考的归一化位移最小选择，平局按固定候选索引。预测COM只用于筛选；选中后必须通过真实COM/载荷门槛才能进入抬轮。无可行候选不扩大范围。

筛选用预测COM明确采用当前测量的body坐标COM偏移，经过候选root位姿刚体变换。它不预测关节运动引起的质量再分配，仅是候选启发式；因此即使预测满足10mm，也不能跳过执行后的真实质量加权COM与载荷检查。位移选择代价为三个方向分别除以.04/.06/.08m后的平方和。

目标搜索与执行插值分离：候选网格不是直接跳变动作，必须经过下述参考回溯和执行目标连续性检查。

### 3.3 统一坐标与轮目标

所有几何目标先明确为world坐标。仅用同一个期望完整刚体变换求IK输入：

```text
p_wheel_goal_b = R_root_goal_wb.T @ (p_wheel_goal_w - p_root_goal_w)
```

准备阶段支撑轮world锚点保持不动，不通过追随滑移伪造机身位移已达成。PASS允许按既有滚动阶段对支撑锚点作共同实测XY滚动运输；不得把各轮相对滑移或机身roll/pitch漂移吸收到锚点。活动轮的目标X/Y/Z也先在world构造，再整体变换，禁止只覆盖body Z或混减heading误差。

沿用既有抬轮高度上界、远侧buffer、阶段顺序和实际通过条件，不用提高高度上界来掩盖不可达性。实际FK与资产关节名称映射必须单独验证。

### 3.4 四腿联合可达性与受约束IK

IK是纯张量模块，返回每腿解、残差、原限位/膝分支/工作空间检查、距伸直余量、步数和明确拒绝码。检查包含所有支撑腿与活动腿，不能只让摆动腿成功。

- 采用原DLS参数和最多32次内部迭代，每分量迭代增量上界.25rad；仅接受残差下降且满足原限位及膝分支的迭代步。
- 保持2mm残差上限；新增教师膝绝对角≥.10rad的近伸直保护，不改变环境成功条件。
- 工作空间计算包含ABAD/hip等真实安装偏移；不能将root到轮的欧氏长度直接与`.54m`比较。
- 候选位姿增量最多回溯8次，比例为1、1/2、…、1/128；每次重建完整目标并重新求四腿IK。无可行结果则整行拒绝，禁止截断关节后冒称到达原目标。
- 数学迭代步不等于控制动作变化。最终每个腿关节目标相对上一实际执行目标，20ms步内最多变化.05rad；超出则缩小参考并重新求解，不能事后clip掩盖目标误差。控制dt不同则按2.5rad/s同比约束。
- 原始测量无效、实际关节越界等不通过突然切换nominal目标处理。

候选搜索最多126组，每组四腿各32次；执行参考回溯最多8组，每组四腿各32次。不得无界重试或增加迭代数救场。缓存可复用纯几何结果，但不能复用不同输入的有效性结论。

## 4. 执行提交和失败处理

每步顺序：测量快照→构造候选→支撑/四腿IK校验→实际动作解码与连续性检查→提交参考及输出。分别保存请求目标、接受目标和实测值。只有解有效、上一接受参考已按既有位姿跟踪阈值实测达到时才推进插值进度；插值年龄不是已完成动作的证据。

第一次IK无解立即停轮，冻结阶段、参考及插值进度，标签置无效；若上一接受腿目标仍合法且连续，可保持该目标，不持续追随下坠实角，也不跳回nominal。保持目标不保证物理安全，原实际安全检查必须继续执行。

连续5个控制步无有效解，或活动阶段触发原有失支撑/碰撞/非有限值条件，该行锁定教师示范失败。初始刹稳等待不因尚未四轮承重自动当作活动阶段失支撑，但仍受原环境物理终止及20s限制。失败锁定后不再恢复为合格标签；诊断最多额外采5步记录后结束该行，正式验收将提前失败计入分母，不能丢弃。这个诊断退出规则不修改环境碰撞预算或termination。

单行reset清该行锚点、年龄、上一目标与失败状态，其他行保持。终止前的输入/输出及预算快照保留旧episode身份。新teacher版本与schema单独标记，任何无效/锁定失败轨迹不进入成功示范集。

## 5. 验证顺序与停止条件

1. CPU RED/GREEN：坐标旋转含非零roll/pitch/yaw；COM质量加权/无效数据；安装偏移；四腿可达性、原限位/分支/近伸直；目标连续性；回溯上限；无解冻结；单行reset及terminal身份。测试必须含旧实现会失败的反例。
2. 冻结run2/run3实测状态，比较旧/新目标、残差与拒绝码。这是几何重算，不称完整物理反事实回放。
3. GPU安全边界下独立原生验收：空地支撑准备→四条腿分别抬落→首个10cm障碍→前后轮及相邻障碍衔接→原20s完整课程。首次关键失败即诊断收尾，不直接继续训练。局部测试不得移除原场景碰撞几何来充当完整验收。
4. 本新设计初版加最多两次有证据、单机制修订。若仍失败，提交失败链与新决策，不继续无限调参、不改PD/回合时长/成功门槛、不启动BC。
5. 完整教师按父规格固定5个seed×20回合，平地和10cm各至少95/100。通过后才进入后续学生计划；后续学生mean/sample各至少90/100的10cm验收及平地95/100不变。

新增边界参数和较慢目标变化可能使20s内完不成课程，必须按原时限实测，不能宣称预先可行或延长时限使其通过。

每条逐帧记录绑定env/episode/输入帧/执行后帧，含实际COM及投影近似、三轮载荷、实测/请求/接受root位姿、world/body四轮目标、每腿残差/限位/分支/工作空间余量、回溯次数、上一执行目标与本步处理后动作、冻结原因、碰撞预算及完整receipt。视频和数据对应同次运行并记录SHA，不用旧视频证明新教师。
