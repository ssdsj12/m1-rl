# M1 参考越障控制器独立验证设计

日期：2026-09-18。状态：用户已同意“先复现越障，再适配绕行”的方向，并指定仿真顺序为“先 8 env，后 1024 env”；本规格已按该要求修订，尚未实施。

## 目标与阶段边界

第一阶段只回答：参考目录中已有的 M1 逐轮控制器，在服务器 4090 的现有 amp 环境下，能否真实、稳定地跨过指定的 60 mm 小障碍，并满足主动净空和安全标准。

原 accepted policy/perception 权重缺失，因此本阶段是显式 oracle/teacher 控制器基线，不是原策略复验，不证明当前 AME 策略已学会越障，也不证明自主感知或大障碍绕行。

后续分为两个独立子项目：控制器/示范到 AME 或 student 的交接；适配 M1 运动约束的大障碍选路与执行。本阶段不实现这两个子项目。

## 方案比较与选择

1. **独立验证入口（推荐）**：只在新诊断进程中加载参考配置、控制器与评价逻辑，保留当前 AME 主链。结果可归因，失败不污染训练；代价是需要薄适配层及资产依赖预检。
2. **直接将参考 wrapper 合入 AME**：更快获得表面动作，但同时改变动作含义、控制权和观测链，无法区分改善来自控制器还是学习。第一阶段不采用。
3. **只复制奖励继续长训**：代码量较少，但参考成功依赖分阶段动作控制，复制权重不能复现其机制。第一阶段不采用。

采用方案 1。所有新增入口和报告独立命名，禁止覆盖原训练入口、已有评测结果或模型权重。

## 组件与数据流

### 1. 来源与资产预检

记录解释器、IsaacLab 路径、导入模块实际位置、参考源码哈希、USD 依赖清单和资产哈希。参考 `go2_pvcnn`、wrapper、curriculum 必须来自同一参考源；不能与 amp 的 editable 安装或当前 AME 同名包混用。

递归验证 USD sublayer/reference/mesh 依赖及其解析结果。只允许在独立生成的资产 overlay 中将可找到的同一依赖重定位，不改源资产。不得静默替换为当前 AME 的不同 USD、碰撞体、质量或关节设置。缺失依赖或无法证明等价时，明确报告具体路径并停止。

目前已找到参考目录内 `Go2Pvcnn/assets/m1_panda/m1/ZJ_V3_URDF_V1_0/` 的候选独立 M1 bundle，但仅确认文件存在，尚未验证二进制 USD 的完整依赖与结构。它不是直接使用 Panda 组合机器人配置的授权。

记录源配置的浮动底座、轮关节类型、轮半径、动作缩放、关节顺序和执行器增益。不能把当前 AME 的物理修复不加说明地混入参考基线。

### 2. 独立控制适配器

显式实例化 `M1PvcnnCrossing60mmContactFreePlayEnvCfg`，并显式构造 `M1RslRlEnvWrapper`，确保每步经过原逐轮状态机和 task-space IK。不设置 `lock_legs`，不额外开启 `wave_reference_actions`。

不创建 PPO runner，不加载缺失的 actor/perception，不伪造 checkpoint。输入为固定零策略残差；接近障碍后的触发使用原几何/语义 oracle 路线并逐步记录，标记为 `controller_oracle`。不得以零向量送入 PolicyPlay 后利用隐式 fallback 冒充学习 gate。

记录每步的原始动作、prepared action、phase、gate 来源及控制权。验证腿残差确实为零，最终腿动作来自参考控制器；同时记录轮速闭环行为。

### 3. 场景与物理评价

固定横杆中心相对环境为 `(0.85, -0.20)`，尺寸 `(0.06, 0.16, 0.06) m`；要求右前 FAR 和右后 RAR 主动跨越。不将此结论扩大为四轮全宽横杆或随机障碍越障。

按用户要求，先 8 环境，严格验收通过后再 1024 环境，不运行 1-env 仿真。两种规模均使用足够隔离的场景布置，并验证实际 env origins、碰撞隔离及 scanner 中障碍归属；不能只设置 env_spacing 就假定地形环境已隔离。独立记录相对初始位姿和原有地形坐标偏移，不将世界坐标当作局部坐标。保留参考 seed `20260711` 及其 startup 摩擦/质量随机化，并记录每个环境的实际采样值；固定 seed 不等于没有物理随机化，不静默关闭这些事件。

保留跌倒、非法状态和碰撞失败；关闭成功后的自动重置以收集姿态恢复。诊断 episode 时长明确设置为至少 `(请求步数 + 1) × control_dt`，记录与原 20 秒 Play 配置的差异，防止正常 timeout 打断 1600 步预算。每个环境只以首次 episode 验收，任何提前失败锁存为失败，不能通过后续自动重置洗掉。仍提前发生 timeout 时报告未完成，不将它计作通过。

直接记录仿真状态和传感器输出，不使用此前失败的 `sys.setprofile` 采集路线。采样点必须在自动重置前；若接口只提供重置后状态，先修正诊断接口并测试，不据此宣称净空成立。

### 4. 结果文件与进程状态

每次运行输出独立 manifest、逐步数据和汇总 JSON。包含：代码/资产哈希、配置差异、进程 PID、GPU、请求步数/实际步数、控制模式、所需轮名、phase、净空、横杆接触力、机身姿态/高度、轮速差、reset/failure 计数、退出原因。

进程完成与行为成功为两个字段。只有步数预算完成、报告写出且正常退出才有 `completed=true`；行为标准全部满足才有 `passed=true`。程序退出码 0 本身不代表仿真或任务完成。

不自动重启，不将断点续跑算作单进程完成；若出现退出或卡住，保留最后步号和错误信息，停止扩大测试。

## 验证顺序与通过标准

1. CPU 单元测试：来源检查、资产缺失拒绝、参数契约、控制器接线、门控来源标记、首次 episode 失败锁存、缺失样本拒绝、报告完成语义。先写失败测试再实现。
2. 8 环境 × 32 步启动检查：参考模块路径正确、wrapper 确实被调用、可获得有效状态/接触数据、正常收尾。不算越障成功。
3. 8 环境各 1600 步，三次独立单进程重复运行；每次均需 8/8 满足下面全部条件。失败则定位首个违约阶段，不进入 1024 环境。重复固定几何运行只检验可重复性，不声称泛化。
4. 三次 8-env 严格验收全部通过后，以同一代码/资产版本进行 1024 环境 × 32 步容量检查，记录 GPU4 显存峰值、步耗时、实际环境数、场景隔离和指标有效性。除规模及明确记录的场景排布外，不改变控制参数或安全阈值。OOM、无进展或启动失败即停止，不自动降规模、换卡或重启。
5. 容量检查通过后运行 1024 环境各 1600 步，单进程完整完成并报告全部 1024 个环境。严格通过要求 1024/1024 满足相同标准；不得只抽样成功环境或剔除失败分母。这是控制器并行扩容验证，不是 PPO 更新，也不是 10000 轮训练。记录随机化分布；不假设其前 8 个环境与 8-env 运行逐值一致。

行为标准：

- phase 至少达到 11，机身越过相对起点 `x=1.50 m`；所需轮子实际越过横杆后沿，不能只用机身位移代替轮子通过。
- FAR/RAR 都观测到主动抬升、横杆上方净空和通过后的落地恢复。净空阈值使用实际确认的参考轮半径及 `5 mm` 余量；参考参数为 `0.06 + 0.095 + 0.005 = 0.160 m` 轮心高度。
- 横杆接触力不超过原 `1 N` 门限；身体/腿的障碍碰撞、跌倒、非法状态、提前失败和 reset 均不得存在。数据缺失为失败，不用零填充。
- 姿态、机身高度恢复、动作连续性均使用目标参考配置内的原验收阈值，原样记录在 manifest；阈值必须在运行前从源码确认并冻结，不能根据结果放宽。
- 四轮实际平均角速度最大差不超过 `0.08 rad/s`。统计窗口、每轮样本数、最小/最大/均值同步报告。

若控制器通过，再设计移植到当前 AME 资产/动力学的对照；该对照是适配验证，不能回填为原参考策略复验。
