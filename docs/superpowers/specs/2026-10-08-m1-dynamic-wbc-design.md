# M1 动态全身控制与稳定跨越设计

日期：2026-10-08。状态：用户已回复“按此设计实施”，书面设计已批准；开始分批实施，尚未通过物理跨越验收。
父规格：[接触跨越设计](2026-10-07-m1-contact-crossing-design.md)。
任务：[T306](../../../notes/todo/T306-m1-ame-long-train-stability.md)。
基线：`6db197a`，独立分支 `codex/m1-contact-crossing`。

## 1. 目标及证据

目标仍是单腿逐个提前抬升、滚行越障、远侧稳定落足、无碰撞；不可跨越时安全绕行。
先证明控制器能稳定跨越，再接入 teacher/PPO 和重训，不把辅助控制成功称为模型学会。
四腿分别验证，禁止用同时抬双前腿、双后腿或对角腿替代单腿跨越。

已有实测：8 个环境在第 96 控制步全部满足连续 5 帧的抬升稳定门控，
但第 101 步（ROLL5）row7/FBL 支撑力降至 21.1639 N，未完成落足。
同一时刻静态模型预计该轮为 43.1959 N；全身 COM 最后 5 ms 的横向动量变化
对应约 7.9005 N 合力。此差异支持升级动力学模型，但不是唯一原因证明。
详见[实测记录](../../../notes/log/2026-10-08-m1-lift-handoff.md)。

不选继续扫静态偏移/等待时间：稳定进入 ROLL 后仍失败。
不选只加三维接触力前馈：若轮速度 PD 独立占有驱动力矩，优化力不一定可执行。
采用浮动基全身逆动力学 QP，统一分配三维接触力与全部 16 个关节的总力矩。

## 2. 模块边界与数据合同

- 动力学适配器：输出命名顺序一致的 M、h、接触 Jacobian、运动学导数、
  q/v、真实关节限位/力矩限额、接触几何、全身 COM 与动量。
  M 为 22×22 浮动基矩阵，h 包括重力及速度相关项；不能拿仅重力向量冒充 h。
- 参考生成器：使用已有单腿事件阶段与有界机身参考，输出 COM/姿态、摆轮轨迹、
  支撑轮滚动速度目标；不拥有第二套力矩输出。
- WBC 求解器：输入适配器快照和阶段参考，输出 qdd、接触力、16 维总力矩、
  约束残差、可行性与明确失败原因。
- 执行适配器：唯一拥有 actuator 命令，检查求解结果和最终总力矩，逐物理子步应用。
- 独立验收器：消费 pre-reset 轨迹、几何和子步接触，不信任控制器 success 标签。

所有快照携带 env/episode/step/phase/leg/obstacle identity；过期或非有限数据拒绝执行。
M1 关节按名称映射，不借用 Go2 的顺序、质量、腿长、轮半径或动作维度。
真实接触点必须由当前轮形状和接触信息得到，不能把轮心当切向力作用点。
接触传感器 normal force 和摩擦力分开获取；无法获得摩擦时标记缺失，
不把 normal-only 数据标成合力。root 角速度不能替代整机角动量。

## 3. 动力学与滚动约束

主等式为 `M qdd + h = S^T tau + Jc^T f`。
优化变量为 22 维 qdd、16 维 tau、当前有效支撑点的三维 f。
支撑模式由接触门控确认；摆轮接触力为零，UNLOAD 独立渐减选中轮承重。
同一轮多接触点需按有界点集表示，保留合力及力矩；不能聚合后丢掉接触力矩。

接触约束区分支撑法向、侧向和滚动方向。滚轮转动 DOF 参与 Jacobian；
不能固定轮心三维速度为零而同时要求向前滚动。
建立瞬时材料接触点的无滑滚动关系并正确处理接触点随轮转动迁移的导数，
以已知纯滚动和有限差分 oracle 验证，不能直接差分跳变的 contact patch ID。
法向单边约束、保守摩擦锥内接多面体、总力矩/关节位置与速度边界为硬约束。
摩擦系数来自当前材料组合并记录；不能为求解通过任意调大。

任务优先级：首先满足安全支撑与动力学可行性，使摆轮能提前抬起、越过障碍并在远侧落足；
前进速度与名义姿态可以让位于成功跨越。跨越过程中只要求足以安全完成动作的支撑/机身稳定，
不要求提前恢复到跨越前的原姿态。严格跨越成功后，再尽快恢复原先平衡；恢复能力单独统计，
既不延迟跨越，也不能抵消未跨过、碰撞或擦滑。前进目标可降速至零，但不能牺牲净空/碰撞条件。
软任务允许误差并记录；不可把硬约束松弛隐藏为求解成功。
初期采用可检查残差的 CPU QP oracle 验证小批量；后续训练后端必须与其数值对照，
未验证吞吐及结果一致性前不扩大环境数。

## 4. 执行器所有权与启用流程

新模式默认关闭，仅在诊断环境显式启用。基线 actuator 配置不被覆盖。
WBC 模式使用显式总力矩控制全部 16 DOF；轮速跟踪是 QP 任务，
不再叠加未建模的轮速度 PD；腿也不再叠加独立 implicit position PD。
阻尼、力矩限额和实际施加力矩需读取并纳入模型/检查，禁止双重控制。
先在独立仿真验证静态承重、零速、缓慢滚动和力矩符号，再进入抬轮测试。
切换在新建诊断环境完成，不热切换运行中的训练/演示。

首次动力学适配审计若无法获取完整 M/h 或可靠执行总力矩，停止物理试验并记录阻塞；
不能退化成只换名称的竖直静态前馈。不得修改驱动或 GPU reset 来绕过接口问题。

## 5. 原有安全边界保留

- PREPARE ≤4 s；UNLOAD ≤2 s；LIFT+ROLL+LAND 合计≤4 s；SETTLE/RECOVER 各≤2 s。
- 承重参考相对进入阶段的偏移≤80 mm，速度≤0.04 m/s，加速度≤0.05 m/s²。
  正常向前行驶的路线位移单独记录，不能计入承重参考后反复重置来规避限制。
- 腿关节参考变化率≤0.5 rad/s；现有力矩限额、变化率保护不静默放宽。
- 接触判定>10 N；阶段推进要求其余支撑≥30 N；静态预测仍要求≥35 N。
- roll/pitch≤0.15 rad，倾斜角速度≤0.20 rad/s，已有支撑余量≥0.02 m。
- 碰撞锁存为本事件失败，抖动重置稳定计数；每个环境独立计时/重置。

求解无效、超时或接触异常不得使用未验证解、无限保持旧力矩或全零动作假装恢复。
健康状态先由同一受约束求解器减速、保留有效支撑并仅向已验证安全区域落轮。
恢复无可行解则终止该仿真行并记录失败，不声称安全恢复或真机可用。

## 6. 分阶段验证与训练门槛

1. CPU 合同与动力学 oracle：命名置换、坐标系、M 对称正定、偏置项、
   Jacobian/滚动约束有限差分、静态重力、已知运动、摩擦/限矩不可行、reset 隔离。
   残差使用力/力矩各自单位和尺度报告；公差在执行计划及测试中固定，物理试验后不得倒改。
2. 平地 actuator 验证：静止承重→四轮低速滚动→逐腿 UNLOAD/LIFT/ROLL/LAND/SETTLE。
   原有 8 行逐腿场景、3 组固定种子全部通过，保留每 5 ms 证据；不以平均力掩盖接触丢失。
3. 单障碍四腿独立测试：3–6 cm 和 10 cm 障碍，顶部真实轮包络净空≥5 cm，
   提前离地，轮包络越远边界≥4 cm 后才落足，5 帧稳定承重，无碰撞/reset。
   **优先判定严格跨越成功**；未越过/碰撞/擦滑均先记跨越失败，不能用落地后的
   快速恢复平衡抵消失败。
4. 只有严格跨越成功后，才单独验收落地恢复：从触地扰动恢复到正常四足承重，
   ≤2 s 回到承重参考偏移≤80 mm、线速度≤0.04 m/s、roll/pitch≤0.15 rad、
   倾斜角速度≤0.20 rad/s、支撑余量≥0.02 m，并连续5帧满足接触/稳定条件。
   恢复时间与恢复率单独统计，不混入跨越成功率。
5. 六个前向交替单轮障碍、可落脚间隔、小方块/球体，以及不可跨越大障碍绕行。
   三组固定种子，每个必测场景都先满足严格跨越，再测恢复/绕行，并同时保存视频与
   逐事件指标；失败逐例诊断。
6. 控制器通过后接 teacher/PPO 小 smoke；记录真实动作接管比例和训练观测，
   禁止把仿真 oracle 直接塞进可部署策略。再开展授权重训和独立 policy-only 评估。
   policy-only 不合格时只能报告辅助控制通过，不能交付为自主成功模型。

exposure/attempt/proxy crossing/strict crossing/碰撞/恢复/绕行分开计数。
严格成功以唯一障碍事件为分母，必须所有所需轮通过；缺失证据为 unknown，
无遇障为 unavailable。绝不以抬轮次数替代成功率。
